==============================================================================
 OpenOLMS - INSTALL
==============================================================================

REQUIREMENTS
  - 386 or better; DOS, DOSBox, or a Win9x DOS box.
  - CWSDPMI.EXE (included) - the DPMI host the door needs to run.
  - An archiver on the PATH: PKZIP.EXE / PKUNZIP.EXE (or ARJ / LHA).

STEP 1 - COPY THE FILES
  Make a directory for the door, e.g.  C:\OLMS  , and copy all of these into it:
      OLMS.EXE  CONFIG.EXE  CWSDPMI.EXE  CWSDPMI.DOC  OLMS.CFG
  Make sure PKZIP.EXE / PKUNZIP.EXE are in that directory or on the DOS PATH.

STEP 2 - CONFIGURE
  From that directory run:
      CONFIG.EXE
  Set:
    - System Information : System name, Sysop name, Board ID (1-8 chars).
    - Archiver Programs  : the compress / decompress commands, e.g.
          Compress:    PKZIP.EXE -ex %ARCHIVE% %FILES%
          Decompress:  PKUNZIP.EXE -o %ARCHIVE%
    - Message Areas      : add your JAM / Hudson message areas (number, name,
                           type, path; Hudson also needs the board number).
    - Press  S  to save (writes OLMS.CFG).

STEP 3 - TEST
      OLMS.EXE --version      (should print the version)
      OLMS.EXE /DA            (reads a dropfile, scans areas, builds the .QWK)

STEP 4 - HOOK IT INTO YOUR BBS (RemoteAccess type-7 example)
  Create a door / type-7 menu entry that drops the caller into:
      C:\OLMS\OLMS.EXE /DA
  Give the door node access to its directory and a dropfile (DORINFO1.DEF or
  DOOR.SYS). See docs/RUNNING.md in the source repo for all switches.
